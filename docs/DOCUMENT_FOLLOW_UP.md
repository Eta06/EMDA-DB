# Document prototype follow-up

The initial document interface is bounded and experimental. This checklist records remaining work; it does not waive the [foundation and storage follow-up](FOUNDATION_FOLLOW_UP.md), physical power-loss test, or independent off-host restore drill.

- [x] Add a versioned JSON collection namespace and explicit schema, missing/null and typed-value semantics.
- [x] Add atomic CRUD, upsert, conditional updates, bounded bulk writes, and transactions that can also access unreserved raw keys. Test failure rollback, unique constraints, concurrent writers and acknowledged process termination on both writable backends.
- [x] Add bounded single/compound, unique and partial indexes, indexed equality/range pages, complete collection scans, filtering, scalar sorting and projection. Atomically maintain index and document entries; detect and rebuild damaged declared indexes within small-collection limits.
- [x] Add bounded count/group/sum aggregation and ID-based relationship lookup with explicit semantics and tests.
- [x] Add a real-time serial-history checker for concurrent document transactions, indexed reads, unique-index claims and atomic raw-key updates on both writable backends. A [4,096-history local campaign](../benchmarks/results/2026-11-04-document-concurrent-model.json) checked full-log recovery on tmpfs and the workspace overlay; broader schedules and fault models remain open.
- [x] Extend document serial histories to include pre-cancelled, callback-cancelled and racing-cancellation transactions alongside concurrent document, index and raw-key operations. A [4,096-history local campaign](DOCUMENT_CANCELLATION_HISTORIES_2026_11_05.md) checked both backends, two local filesystems and recovery after each history; wider schedules and storage-fault combinations remain open.
- [x] Run [longer recovery, checkpoint, incremental-index and schema-migration fuzz campaigns](EXTENDED_RECOVERY_FUZZ_2026_11_05.md) on `4a2df54`, including 38,587 generated document-model executions without a finding. These serial runs do not cover concurrent schedules or physical power loss.
- [x] Exercise 800 [document transaction process-kill races](DOCUMENT_KILL_RACES_2026_11_05.md) across both writer backends and two local filesystems; all recovered acknowledged document/index/raw-key transactions, with the interrupted transaction fully present or absent. This is not physical power-loss validation.
- [ ] Expand transaction history/model checking and longer interruption/storage-fault campaigns specifically for document/index operations. A [three-minute-per-target model run](../benchmarks/results/2026-11-04-online-document-fuzz.json) exercised 14,802 incremental-index and 16,292 schema-migration inputs without a finding; these serial generated cases do not exhaust concurrent histories or model physical power loss. Targeted V2 partial-log and V3 metadata-failure tests verify that document, unique index and raw-key updates recover together or fail closed; local backup/restore covers both writable backends. Run longer fuzz campaigns and retain any reproducer. A process kill is not a power failure.
- [x] Run index, schema and document recovery suites plus targeted V3 metadata-fault checks on the workspace overlay; the [record](../benchmarks/results/2026-11-04-overlay-recovery-checks.json) includes counts and limitations. Its backing device was not independently verified; this is not a physical power-loss or off-host test.
- [x] Publish an [initial single-client document comparison](DOCUMENT_COMPARISON_2026_11_04.md) with raw samples, verified content, durable settings and adapter differences. This small hot workload does not establish concurrent, large-dataset, recovery or resource behavior.
- [x] Measure and remove the full-index copy from ordinary standalone document `get`, retaining conservative conflict and health checks. The [before/after comparison](DOCUMENT_POINT_READ_COMPARISON_2026_11_04.md) records raw samples and remaining workload differences, plus a 10,399-input document-model fuzz run; indexed queries and transactions retain bounded snapshots, and writes may copy the index.
- [x] Measure ordinary-store shared snapshots against the prior engine and SQLite at 0–3,000 indexed documents, and under concurrent reader/writer contention. The [report](SHARED_SNAPSHOT_COMPARISON_2026_11_04.md) records improvements, regressions, adapters and raw samples; broader workloads remain open.
- [ ] Measure and optimize document workloads with equivalent durability and comparable behavior against SQLite, MongoDB and other suitable alternatives. Publish workload definitions, distributions, concurrency, resource use, failures and noise; do not infer performance from the earlier byte-key baseline.
- [x] Add resumable incremental index build and drop with atomic progress, bounded per-step work, writer coordination and recovery checks. Unique constraints take effect only after successful publication, and callers schedule and retry steps. The ordinary backend still has transaction snapshot limits; this is not a total-memory or latency guarantee.
- [x] Add resumable schema validation and publication with durable progress, per-step limits and enforcement of both schemas on concurrent writes. One-shot schema changes and index rebuilds still have small limits; incompatible schemas can require removing documents or cancelling the job.
- [x] Add bounded atomic push, add-unique, remove-all-equal and first/last pop operators for JSON arrays. Both backends enforce schemas and scalar-index restrictions; missing, null, non-array, conflict, recovery, work-limit and rollback behavior are tested. Two [reference-model fuzz runs](../benchmarks/results/2026-11-04-document-array-fuzz.json) exercised 11,970 generated inputs. [Failure injection](../benchmarks/results/2026-11-04-document-array-faults.json) covered every byte cut of an atomic array/index/raw-key update on V2 and V3 logs, plus selected synchronization, metadata and panic failures on tmpfs and the workspace overlay. Multikey indexing and broader array queries remain open.
- [x] Add an opt-in rule-based unique equality index selection for filtered queries, with explicit fallback, access-path reporting, transactional phantom checks and corruption-limit documentation. The [local comparison](DOCUMENT_QUERY_PLANNER_COMPARISON_2026_11_04.md) includes full-scan, planned, explicit-index and SQLite measurements. The [metadata-reuse follow-up](PLANNER_METADATA_COMPARISON_2026_11_04.md) records paired measurements, mixed tails and a repeat. Two [differential fuzz runs](../benchmarks/results/2026-11-04-document-query-planner-fuzz.json) exercised 10,121 generated inputs. At that revision nonunique, range, compound and partial index planning, statistics and cost-based selection remained open.
- [x] Add bounded array contains, any, all and exact-length query predicates, with exact JSON equality, explicit missing/null and empty-list semantics, nested-value support, shared input/comparison budgets, aggregation and scalar-index residual filtering. Both writable backends, recovery, real-time phantom conflicts and limit failures are tested. Two [clean-seed model fuzz runs](../benchmarks/results/2026-11-04-document-array-query-fuzz.json) exercised 14,502 generated cases without a finding. Multikey indexes and further array operators remain open.
- [x] Reject an oversized corrupt indexed document before applying the page byte budget, so it cannot appear as an empty last page. Tests reproduce the original issue on both writable backends and verify both normal maximum-size pagination and detection on a later page. This does not detect missing index entries caused by unsupported reserved-key writes.
- [x] Extend opt-in planning to complete nonunique single-field equality ranges, preferring unique indexes and retaining candidate-count and exact encoded-byte budgets across pages. Both writable backends, recovery, sort/projection, multi-page phantom detection, rollback and corrupt-index handling are tested. Two [model fuzz runs](../benchmarks/results/2026-11-04-nonunique-planner-fuzz.json) exercised 12,022 cases; the [comparison](NONUNIQUE_QUERY_COMPARISON_2026_11_04.md) reports scans, the planned path and SQLite, including a repeat and an earlier invalid scan baseline. At that revision range, compound and partial planning and cost estimates remained open.
- [x] Investigate skipping the last empty nonunique-index page using a conservative scan-exhaustion signal. The [experiment](SCAN_EXHAUSTION_EXPERIMENT_2026_11_04.md) retained both patches and raw results but rejected them because the measured gains were not repeatable and some latencies regressed. The active engine keeps its existing pagination and validation behavior.
- [x] Plan bounded single-field scalar ranges using required comparisons, intersected inclusive/exclusive bounds and the index scalar ordering. Candidate results are restored to ID order before filtering and pagination. Both writable backends, mixed scalar types, multi-page results, staged changes, byte and candidate budgets, corrupt entries and phantom conflicts are tested. Two [differential fuzz runs](../benchmarks/results/2026-11-04-range-planner-fuzz.json) exercised 18,519 generated cases; the [comparison](RANGE_QUERY_COMPARISON_2026_11_04.md) reports the planned path, scans and SQLite with a repeat. At that revision compound and partial planning and cost estimates remained open.
- [x] Plan complete equality tuples on unique and nonunique compound indexes, requiring every indexed field to be constrained so omitted missing-field documents cannot disappear. Both backends, four-field tuples, partial-tuple fallback, multi-page limits, staged changes, corruption, recovery and phantom conflicts are tested. Two [differential fuzz runs](../benchmarks/results/2026-11-04-compound-planner-fuzz.json) exercised 22,782 generated cases; the [comparison](COMPOUND_QUERY_COMPARISON_2026_11_04.md) reports the planned path, scans and SQLite with a repeat. At that revision compound ranges, partial-index planning and cost estimates remained open.
- [x] Select a partial index only when required predicates prove its presence, absence or typed equality condition. Complete equality tuples and single-field ranges support this conservative implication on both writable backends; fallback, null versus missing, typed values, candidate and byte limits, multi-page phantom conflicts, staged updates, corruption and recovery are tested. A [differential fuzz campaign](../benchmarks/results/2026-11-04-partial-planner-fuzz.json) exercised 12,665 partial-index and 3,986 compound-index regression inputs without a finding. The [comparison](PARTIAL_QUERY_COMPARISON_2026_11_04.md) includes SQLite, a repeat and an unresolved execution-order effect. At that revision compound ranges, general boolean implication and cost estimates remained open.
- [x] Stream bounded collection filtering and retain only the requested unsorted result window while still validating every record and enforcing the full scan/byte limits. Tests cover both backends, recovery, pagination, sort/projection and error precedence. Two [model/differential campaigns](../benchmarks/results/2026-11-04-stream-scan-fuzz.json) exercised 17,210 inputs; the [paired comparison](STREAM_SCAN_COMPARISON_2026_11_04.md) includes a repeat, SQLite and VM noise. A [combined-branch run](../benchmarks/results/2026-11-04-stream-merged-fuzz.json) exercised 6,097 partial-planner and 2,801 checkpoint-limit inputs. This is not a total-memory quota.
- [x] Plan scalar ranges following an equality prefix on compound indexes only when every later indexed field is proven present; support safely implied partial indexes. Both backends, mixed scalar types, missing/null behavior, four-field indexes, unique ranges, pagination, candidate and byte limits, staged changes, corruption, recovery and concurrent phantoms are tested. [Differential fuzz runs](../benchmarks/results/2026-11-04-compound-range-fuzz.json) include 6,074 corrected-generator cases and document an earlier generator limitation. The [cross-engine comparison](COMPOUND_RANGE_QUERY_COMPARISON_2026_11_04.md) includes SQLite, PostgreSQL and MongoDB with a repeat and explicit adapter differences. General boolean implication and cost-based selection remain open.
- [x] Include equality values in the shared filter input and comparison budgets, including unreachable branches, with scan/planner/aggregation rollback coverage on both backends. [Model fuzzing and before/after SQLite measurements](EQUALITY_FILTER_BUDGET_2026_11_05.md) record overhead, regressions and adapter limits; this can reject previously accepted queries and is not a total resource quota.
- [x] Add bounded `In` and `NotIn` predicates with exact whole-value equality, explicit missing/null behavior, shared array-filter budgets and safe singleton index planning. Both backends, transactional staged changes and phantom conflicts, recovery, aggregation, partial-index implication, mixed filter budgets and compound suffix presence have targeted tests. [Model and regression fuzz runs](../benchmarks/results/2026-11-04-document-membership-fuzz.json) exercised 11,394 membership and 7,386 array-query cases. Array-element matching remains separate work.
- [x] Plan a union of deduplicated scalar probes for a required multi-value `In` on an eligible single-field index, including safely implied partial indexes. Candidate and byte limits are shared across probes; results retain ID ordering and normal transaction conflict checks. Both backends, pagination, typed values, fallback, staged writes, concurrent phantoms, recovery, corruption and cumulative limits have targeted tests. [Fuzz campaigns](../benchmarks/results/2026-11-04-document-membership-union-fuzz.json) exercised 15,084 union, 2,384 existing membership and 3,792 compound-range cases. The [SQLite comparison](MEMBERSHIP_UNION_COMPARISON_2026_11_04.md) includes a repeat and raw samples. At that revision compound and multikey unions remained open.
- [x] Plan a bounded union of complete compound equality/membership tuples, including implied partial indexes. Both writable backends check typed values, duplicate probes, the 256-tuple cap, missing and non-indexable fallback, staged changes, phantom conflicts and candidate limits. [Fuzzing and measured SQLite comparisons](COMPOUND_MEMBERSHIP_COMPARISON_2026_11_04.md) include 36,041 generated cases and raw latency samples; SQLite's indexed path was faster on the sampled workloads. Broader compound prefixes, range/membership combinations and multikey unions remain open.
- [x] Add grouped count, exact integer sum, minimum, maximum and approximate mean for up to 16 fields on bounded complete scans. Both writable backends cover empty groups, null and missing values, exact large sums, bounds, invalid inputs, rollback, transaction phantoms and recovery. A [23,960-input model campaign](../benchmarks/results/2026-11-04-aggregate-stats-fuzz.json) exercised generated serial cases. The [SQLite comparison](AGGREGATE_STATS_COMPARISON_2026_11_04.md) includes a repeat and raw samples; SQLite was faster on this workload with different data representations. This is not a general aggregation pipeline or indexed aggregation.
- [x] Stream matched documents into grouped statistics while retaining complete-scan validation and error precedence. Both backends cover later scan/filter failures, transaction phantoms and recovery; a [19,782-input model run](../benchmarks/results/2026-11-04-aggregate-stream-fuzz.json) includes array filters. A [paired comparison](AGGREGATE_STREAM_COMPARISON_2026_11_04.md) shows lower sampled prototype latency, while SQLite remained faster with different data representations. Groups and a scan page are still retained; this is not a total-memory quota.
- [x] Add ordered set-if-missing, checked signed multiplication, typed scalar minimum/maximum and non-overlapping field rename updates. Both writable backends cover missing/null semantics, overlap and type errors, schema/unique-index rollback, raw-key atomicity, concurrent conflicts and recovery. The shared array/scalar fault model checks 351 V2 and 351 V3 append cut points and selected metadata failures, ensuring document, index and raw-key changes recover together or fail closed. A [50-run local stress campaign](../benchmarks/results/2026-11-04-scalar-update-stress.json) repeated these faults and concurrent updates on tmpfs and the workspace overlay; [model fuzzing](../benchmarks/results/2026-11-04-scalar-update-fuzz.json) exercised 13,652 scalar and 4,283 array cases. The operator set remains limited and is not MongoDB compatible.
- [x] Bound combined encoded-JSON condition and value inputs for one document update to 4 MiB, counting repeated inputs and escapes before evaluating conditions. Both backends cover exact and over-limit mixed operations, no-op updates and raw-key rollback. [Model fuzzing](../benchmarks/results/2026-11-04-update-input-fuzz.json) exercised 43,508 cases across three revisions; [paired measurements](UPDATE_INPUT_COMPARISON_2026_11_04.md) show both the cost of the new limit and the effect of optimized exact accounting. This does not bound caller allocations, total memory or CPU.
- [x] Run combined [admission, input-counting and document regression models](../benchmarks/results/2026-11-04-admission-input-merged-fuzz.json) on the merged implementation; the four short campaigns exercised 44,576 cases. Wider fault and concurrency coverage remains open.
- [ ] Design richer schema types and validation, comparison/update/aggregation operators, array and multikey behavior, broader compound index unions, relationships, diagnostics, statistics and a cost-based planner; define compatibility and limits before implementation. Current lookups are by ID, aggregation is limited, and unplanned or ineligible collection queries require a complete bounded scan.
- [ ] Consider durable cursors/snapshots, cancellation, request budgets and more scalable transactions. Page calls outside one transaction can observe intervening writes. Existing budgets are not total memory or project quotas.
- [ ] Add an authenticated service and genuine project isolation in the later security/service priority. The raw reserved prefix is not an isolation boundary; uncooperative raw writes can corrupt document metadata or create undetected omissions until bounded verification.
- [ ] Establish versioned migration, import/export and compatibility policy before a stable release. Neither MongoDB wire/query compatibility nor a downgrade promise exists.
