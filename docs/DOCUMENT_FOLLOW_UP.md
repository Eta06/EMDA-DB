# Document prototype follow-up

The initial document interface is bounded and experimental. This checklist records remaining work; it does not waive the [foundation and storage follow-up](FOUNDATION_FOLLOW_UP.md), physical power-loss test, or independent off-host restore drill.

- [x] Add a versioned JSON collection namespace and explicit schema, missing/null and typed-value semantics.
- [x] Add atomic CRUD, upsert, conditional updates, bounded bulk writes, and transactions that can also access unreserved raw keys. Test failure rollback, unique constraints, concurrent writers and acknowledged process termination on both writable backends.
- [x] Add bounded single/compound, unique and partial indexes, indexed equality/range pages, complete collection scans, filtering, scalar sorting and projection. Atomically maintain index and document entries; detect and rebuild damaged declared indexes within small-collection limits.
- [x] Add bounded count/group/sum aggregation and ID-based relationship lookup with explicit semantics and tests.
- [x] Add a real-time serial-history checker for concurrent document transactions, indexed reads, unique-index claims and atomic raw-key updates on both writable backends. A [4,096-history local campaign](../benchmarks/results/2026-11-04-document-concurrent-model.json) checked full-log recovery on tmpfs and the workspace overlay; broader schedules and fault models remain open.
- [x] Repeat [4,096 document histories](../benchmarks/results/2026-11-14-shared-view-concurrent-histories.json) on `5672d37` after checkpoint-view handle sharing, across tmpfs and workspace overlay, both writable backends and full-log recovery. These are finite clean-reopen schedules, not injected-fault or power-loss tests.
- [x] Check a controlled read-set interleaving of schema and unique-index publication with a concurrent pre-cursor insert, in both publication orders and on both writable backends. The losing publication conflicts and its raw witness remains absent; clean reopens preserve the winning state. Wider interleavings and injected faults remain open.
- [x] Check an empty index-build publication page against a concurrent post-cursor insert on both writable backends. Publication conflicts and rolls back its raw witness; after clean reopen, the retry indexes the inserted document before publishing. This covers one scheduled phantom, not all index-maintenance races.
- [x] Stage a read-set writer under the old schema, then start and publish a stricter migration before releasing it. On both writable backends the stale writer conflicts, its document and raw witness remain absent after clean reopen, and the published schema rejects invalid inserts. - [x] Extend document serial histories to include pre-cancelled, callback-cancelled and racing-cancellation transactions alongside concurrent document, index and raw-key operations. - [x] Chain real-time document histories without resetting state between windows. The model alternates ordinary and checkpoint writers on the same store, checks both recovery paths after every window and creates a fresh checkpoint every 16 windows. Its seven concurrent calls include unique-index claims and release by document deletion. The model rejects a successful new claim after a cancelled release. On Linux ARM64 ext4, 2,048 windows each on V2 and V3 passed, with 28,672 attempted calls, 8,192 recovery checks, and 1,410 committed releases of existing claims. On macOS V2, 1,024 windows passed, with 7,168 attempted calls, 2,048 recovery checks, and 348 committed releases. Reproduce with `EMDA_CHAINED_DOCUMENT_MODEL_WINDOWS=2048 cargo test --locked --test document_transaction_model chained_document_histories -- --nocapture`. These runs sampled concurrent schedules and clean process-local closes.
