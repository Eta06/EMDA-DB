# Document prototype follow-up

The initial document interface is bounded and experimental. This checklist records remaining work; it does not waive the [foundation and storage follow-up](FOUNDATION_FOLLOW_UP.md), physical power-loss test, or independent off-host restore drill.

- [x] Add a versioned JSON collection namespace and explicit schema, missing/null and typed-value semantics.
- [x] Add atomic CRUD, upsert, conditional updates, bounded bulk writes, and transactions that can also access unreserved raw keys. Test failure rollback, unique constraints, concurrent writers and acknowledged process termination on both writable backends.
- [x] Add bounded single/compound, unique and partial indexes, indexed equality/range pages, complete collection scans, filtering, scalar sorting and projection. Atomically maintain index and document entries; detect and rebuild damaged declared indexes within small-collection limits.
- [x] Add bounded count/group/sum aggregation and ID-based relationship lookup with explicit semantics and tests.
- [x] Add a real-time serial-history checker for concurrent document transactions, indexed reads, unique-index claims and atomic raw-key updates on both writable backends. A [4,096-history local campaign](../benchmarks/results/2026-11-04-document-concurrent-model.json) checked full-log recovery on tmpfs and the workspace overlay; broader schedules and fault models remain open.
- [ ] Expand transaction history/model checking and longer interruption/storage-fault campaigns specifically for document/index operations. A [three-minute-per-target model run](../benchmarks/results/2026-11-04-online-document-fuzz.json) exercised 14,802 incremental-index and 16,292 schema-migration inputs without a finding; these serial generated cases do not exhaust concurrent histories or model physical power loss. Targeted V2 partial-log and V3 metadata-failure tests verify that document, unique index and raw-key updates recover together or fail closed; local backup/restore covers both writable backends. Run longer fuzz campaigns and retain any reproducer. A process kill is not a power failure.
- [x] Run index, schema and document recovery suites plus targeted V3 metadata-fault checks on the workspace overlay; the [record](../benchmarks/results/2026-11-04-overlay-recovery-checks.json) includes counts and limitations. Its backing device was not independently verified; this is not a physical power-loss or off-host test.
- [x] Publish an [initial single-client document comparison](DOCUMENT_COMPARISON_2026_11_04.md) with raw samples, verified content, durable settings and adapter differences. This small hot workload does not establish concurrent, large-dataset, recovery or resource behavior.
- [x] Measure and remove the full-index copy from ordinary standalone document `get`, retaining conservative conflict and health checks. The [before/after comparison](DOCUMENT_POINT_READ_COMPARISON_2026_11_04.md) records raw samples and remaining workload differences, plus a 10,399-input document-model fuzz run; indexed queries and transactions retain bounded snapshots, and writes may copy the index.
- [x] Measure ordinary-store shared snapshots against the prior engine and SQLite at 0–3,000 indexed documents, and under concurrent reader/writer contention. The [report](SHARED_SNAPSHOT_COMPARISON_2026_11_04.md) records improvements, regressions, adapters and raw samples; broader workloads remain open.
- [ ] Measure and optimize document workloads with equivalent durability and comparable behavior against SQLite, MongoDB and other suitable alternatives. Publish workload definitions, distributions, concurrency, resource use, failures and noise; do not infer performance from the earlier byte-key baseline.
- [x] Add resumable incremental index build and drop with atomic progress, bounded per-step work, writer coordination and recovery checks. Unique constraints take effect only after successful publication, and callers schedule and retry steps. The ordinary backend still has transaction snapshot limits; this is not a total-memory or latency guarantee.
- [x] Add resumable schema validation and publication with durable progress, per-step limits and enforcement of both schemas on concurrent writes. One-shot schema changes and index rebuilds still have small limits; incompatible schemas can require removing documents or cancelling the job.
- [x] Add bounded atomic push, add-unique, remove-all-equal and first/last pop operators for JSON arrays. Both backends enforce schemas and scalar-index restrictions; missing, null, non-array, conflict, recovery, work-limit and rollback behavior are tested. Two [reference-model fuzz runs](../benchmarks/results/2026-11-04-document-array-fuzz.json) exercised 11,970 generated inputs. [Failure injection](../benchmarks/results/2026-11-04-document-array-faults.json) covered every byte cut of an atomic array/index/raw-key update on V2 and V3 logs, plus selected synchronization, metadata and panic failures on tmpfs and the workspace overlay. Multikey indexing and broader array queries remain open.
- [x] Add an opt-in rule-based unique equality index selection for filtered queries, with explicit fallback, access-path reporting, transactional phantom checks and corruption-limit documentation. Nonunique, range, compound and partial index planning, statistics and cost-based selection remain open.
- [ ] Design richer schema types and validation, comparison/update/aggregation operators, array and multikey behavior, relationships, diagnostics, statistics and a cost-based planner; define compatibility and limits before implementation. Current lookups are by ID, aggregation is limited, and collection queries require a complete bounded scan.
- [ ] Consider durable cursors/snapshots, cancellation, request budgets and more scalable transactions. Page calls outside one transaction can observe intervening writes. Existing budgets are not total memory or project quotas.
- [ ] Add an authenticated service and genuine project isolation in the later security/service priority. The raw reserved prefix is not an isolation boundary; uncooperative raw writes can corrupt document metadata or create undetected omissions until bounded verification.
- [ ] Establish versioned migration, import/export and compatibility policy before a stable release. Neither MongoDB wire/query compatibility nor a downgrade promise exists.
