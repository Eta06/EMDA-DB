# Document cancellation history checks

The document serial-history checker now mixes conservative, read-set and deadline-enabled FIFO transactions with three controlled paths: a pre-cancelled token, cancellation after the operation callback completes, including after successful staging, and a separate thread racing cancellation against a read-set transaction. Every history runs six concurrent operations that transfer balances, reset balances, read data and indexes, or compete for a unique claim. The checker requires completed observations and the final state to match a real-time-compatible serial order. Conflicts, duplicate claims and engine-confirmed cancellations do not change the model state. A negative test verifies that the checker rejects a state change attributable only to cancelled work.

After each history, the test checks the documents, raw mirror, unique and nonunique indexes, and collection integrity, then drops the original handle and checks the same state after ordinary full-log recovery. Engine-confirmed cancellation is treated as an abort because it is reported before staged writes are submitted. The test does not classify arbitrary commit I/O errors as aborted; unexpected errors fail the run.

The [local record](../benchmarks/results/2026-11-05-document-cancellation-histories.json) contains 4,096 histories: 1,024 per writable backend on each of tmpfs and the workspace overlay. Across 24,576 operation events, 11,906 were engine-confirmed cancellations, 6,669 completed, and 6,001 returned conflicts or duplicate-claim errors. The test includes deliberate pre-cancellation, so the totals alone do not establish how often cancellation reached every possible internal wait or commit boundary. Each run completed and all recovered states matched its model. The tmpfs and workspace campaigns took 93.50 and 105.77 seconds respectively, including repeated initialization, synchronization and reopening; these are stress durations, not latency benchmarks.

The normal targeted test and clippy passed on both stable Rust and Rust 1.85. This finite stress run exercises some scheduler interleavings, not all possible concurrent histories, deadline races, I/O fault combinations or physical power-loss states. It is not a proof of production isolation, total resource bounds or off-host disaster recovery. The broader [document](DOCUMENT_FOLLOW_UP.md) and [foundation](FOUNDATION_FOLLOW_UP.md) checklists remain open.
